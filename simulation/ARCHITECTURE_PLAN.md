# Архитектура и План Реализации Симулятора Volnix Protocol

## 1. Концепция и Цель проекта
Создание интерактивной веб-симуляции (Backend + Frontend) для демонстрации, тестирования и глубокого анализа ключевых механизмов блокчейна Helvetia Protocol (модули `ident`, `lizenz`, `anteil`, `consensus`). 

**Ключевая особенность:** Симулятор является **централизованным единым источником истины**. Бэкенд полностью имитирует работу блокчейна. Доступ ко всем кошелькам, ролям и управлению сетью осуществляется **исключительно через единую панель оператора симуляции**. Это идеальная песочница для аналитики, стресс-тестов и отладки экономики.

## 2. Предлагаемая Архитектура

### 2.1. Общая схема
Система состоит из двух компонентов, взаимодействующих по REST API и WebSocket:
1. **Simulation Engine (Backend)**: Серверная часть, хранящая in-memory состояние блокчейна, генерирующая блоки, обрабатывающая транзакции и симулирующая фоновую активность (ботов).
2. **Simulation Dashboard (Frontend)**: Единый интерфейс, объединяющий панель оператора симуляции, блокчейн-эксплорер и рыночную аналитику.

### 2.2. Backend (Simulation Engine)
- **Стек**: Python (FastAPI) для обеспечения высокой производительности, удобной работы с асинхронностью и WebSocket.
- **Компоненты**:
  - **State Manager**: Хранилище текущего состояния (аккаунты, балансы, ордера, лицензии, роли).
  - **Mempool**: Очередь ожидающих транзакций.
  - **Mock Consensus Loop**: Фоновый процесс генерации блоков. Скорость генерации (Block Time) динамически управляется через API в широком диапазоне.
  - **Traffic Generator (Bot Engine)**: Встроенный модуль для имитации постоянной сетевой активности. Автоматически управляет пулом из нескольких десятков кошельков, совершая случайные переводы, выставляя ордера и меняя роли для создания реалистичной нагрузки и рыночной динамики.
  - **Sim Operator API** (`/api/sim-operator/…`): эндпоинты для административного вмешательства (минт токенов, смена ролей, управление ботами).
  - **Analytics API & WebSocket Layer**: REST для исторических данных и WS для стриминга состояния (блоки, транзакции, стакан ордеров) в реальном времени.

### 2.3. Frontend (Simulation Dashboard)
- **Стек**: React + TypeScript + Vite, графики (Recharts/Lightweight Charts).
- **Основные модули интерфейса**:

  **1. Панель оператора симуляции**
  - **Управление временем**: скорость симуляции **от 1:1 до «1 с = 1 неделя»** (×604800, batch-режим движка ≈ 10080 блоков/с, фактический темп ограничен CPU); совместимый ручной интервал блока 0.1–300 с.
  - **Global Wallet & Role Manager**: Единая таблица всех существующих кошельков (включая ботов). Возможность в 1 клик:
    - Создать новый кошелек.
    - Назначить/изменить статус (Гражданин, Поставщик, Валидатор).
    - Начислить/списать любые суммы токенов.
    - Отправить транзакцию от имени *любого* выбранного кошелька.
  - **Bot Control**: Включение/выключение генератора фонового трафика, настройка интенсивности переводов.

  **2. Blockchain Explorer (Анализ сети)**
  - **Лента блоков**: Мониторинг высоты, хешей, количества транзакций в блоке.
  - **Лента транзакций**: Детальный просмотр каждой операции (переводы, выдача ролей, матчинг ордеров).
  - **Network Stats**: Графики TPS (транзакций в секунду), времени блока, общего количества аккаунтов.

  **3. Market Analytics (Рынок модуля Anteil)**
  - **Биржевой стакан (Orderbook)**: Визуализация спроса и предложения в реальном времени.
  - **График цены**: Свечной график или линейный график изменения цены токена/долей на основе матчинга ордеров.
  - **Торговая история**: Список последних исполненных сделок.

## 6. Симулятор v2 — поправки к канону (реализовано)

Движок переведён на **ruleset v2** — модифицированный набор правил, решающий
критичные проблемы канона v4.20 из `docs/CANON_PROBLEMS.md`
(спецификация поправок: `simulation/docs/V2_RULESET.md`):

| Поправка | Суть | Статус |
|---|---|---|
| λ — только верхний предел | `Σb_i ≤ λ·L_total`; минимальный порог удалён, блок валиден при любом Σb_i (включая 0) — liveness не зависит от рынка ANT; при `b_i = 0` нет ни базовой WRT, ни комиссий | ✅ |
| Genesis без «курицы-яйца» | стартовый ANT валидатора = `EpochBlocks × λ × L_genesis` (бюджет сжигания на эпоху) | ✅ |
| `s_i` — возвращаемая ставка | сжигается только `b_i`; `s_i` проверяется по балансу (`ANT ≥ b+s`), задаёт вес `w_i = s_i/L_i`, но не списывается | ✅ |
| Детерминированный EndBlocker | tie-breaker при равных `w_i` — лексикографически по адресу; единый порядок: валидация → λ-отсев → top-K | ✅ |
| Фиксированный wipe эпохи | (1) отмена SELL-ордеров Поставщиков с возвратом эскроу → (2) сжигание всего ANT Поставщиков → (3) эмиссия; BUY-ордера переживают границу | ✅ |
| Стабильный коэффициент эмиссии | `sold_prev ≈ 0` → coeff не меняется; EMA-сглаживание (α = 0.5); клиппинг [0.75, 1.5] | ✅ |
| Rollback отклонённых блоков | блок, отклонённый кворумом или инвариантами, полностью откатывает состояние | ✅ |
