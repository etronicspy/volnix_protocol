# Ruleset v2 симулятора — поправки к канону v4.20

Симулятор (начиная с «симулятора v2») реализует **модифицированный набор правил**
относительно канона `docs/volnix_protocol.md` (v4.20). Поправки решают проблемы,
зафиксированные в `docs/CANON_PROBLEMS.md` (номера ниже ссылаются на этот файл).
Это **предложение к следующей версии спецификации**, проверяемое на R&D-стенде.

## Сводка изменений

| # | Проблема канона | Решение v2 | Где в коде |
|---|---|---|---|
| 1 | «Коридор» `Σb_i ≥ λ·L_total` и `Σb_i ≤ λ·L_total` — фактически точка; liveness зависит от рынка ANT | **Только верхний предел** `Σb_i ≤ λ·L_total`. Минимальный порог удалён: блок валиден при любом `Σb_i ≥ 0`, включая 0 | `engine._finalize_declares_batch`, `engine._produce_block_body` |
| 2 | Genesis «курица-яйцо»: валидатору нужен ANT для `b_i`, но WRT для покупки ANT даётся только за `b_i > 0` | Genesis-валидатор получает **стартовый ANT = EpochBlocks × λ × L_genesis** (бюджет сжигания на одну полную эпоху) | `state.GENESIS_VALIDATOR_ANT_BALANCE` |
| 3 | Сжигание `s_i` каждый блок — ловушка капитала, хрупкая зависимость от непрерывного рынка ANT | **Сжигается только `b_i`**; `s_i` — возвращаемая ставка на высоту: проверяется `ANT ≥ b_i + s_i`, определяет вес `w_i = s_i/L_i`, но не списывается | `engine._finalize_declares_batch` |
| 5 | `ratio = sold_cur/sold_prev` численно нестабилен (деление на ноль, дёрганая политика) | `sold_prev ≈ 0 → coeff не меняется`; иначе EMA-сглаживание: `coeff' = α·(coeff/ratio) + (1−α)·coeff`, `α = 0.5`; клиппинг `[0.75, 1.5]` сохранён | `engine._epoch_boundary`, `EMISSION_COEFF_ALPHA`, `SOLD_PREV_FLOOR` |
| 6 | Wipe эскроу/ордеров на границе эпохи недоопределён (fork risk) | **Фиксированный алгоритм**: (1) отменить SELL-ордера Поставщиков, вернуть эскроу; (2) сжечь весь ANT Поставщиков; (3) зачислить эмиссию. BUY-ордера Валидаторов переживают границу | `engine._epoch_boundary` |
| 10 | Tie-breaker top-K «например по адресу» — не норма (fork risk) | **Нормативно**: при равных `w_i` — лексикографический порядок адресов по возрастанию; единый порядок шагов EndBlocker: валидация → λ-отсев снизу по весу → top-K → фиксация ValidatorSet | `engine._finalize_declares_batch` |

## Следствия удаления минимального порога (№1)

- **Liveness не зависит от рынка ANT**: цепь растёт даже при `Σb_i = 0`
  (пустые блоки), нет «ручной координации валидаторов» из канона v4.20.
- Стимул объявлять `b_i` сохраняется экономикой, а не порогом: при `b_i = 0`
  валидатор не получает **ни базовой эмиссии WRT (§5.1), ни доли комиссий (§5.4)**.
- Эталонная стратегия клиента (реализована в `AutoDeclareDaemon`):
  каждый валидатор объявляет `b_i = λ·L_i`; тогда `Σb_i = λ·L_total` — сеть
  работает ровно на верхнем пределе без внепротокольной координации,
  λ-отсев не срабатывает.
- Запись `block_reward_skipped` в ленте блока теперь означает «на высоте не было
  валидаторов с `b_i > 0`», а не отказ блока.

## Следствия возвращаемой ставки `s_i` (№3)

- Валидатор «горит» капиталом только на `b_i`; ставка `s_i` — оборотный залог
  веса, а не расход. Спрос на ANT становится равномернее и предсказуемее.
- Требование `ANT ≥ b_i + s_i` на момент исполнения declare сохранено: нельзя
  ставить один и тот же ANT и в сжигание, и в вес.
- Счётчик `current_epoch_burn` учитывает только фактически сожжённый `b_i`
  (KPI burn ratio становится точнее).

## Прочие уточнения консенсуса v2

- Блок, **отклонённый кворумом** PreVote/PreCommit, полностью откатывает
  состояние (в v1 мутации DeliverTx могли «протекать» без блока). Evidence
  double-sign при этом сохраняется в журнале нарушений.
- Отказ по инвариантам (пустой ValidatorSet, отрицательный баланс) также
  откатывает состояние перед ошибкой.

## Что НЕ менялось

- Верхний предел λ (genesis `1/3`), потолок подписантов `K = 150`, лимит
  `b_i + s_i ≤ L_i`, потолок активации `⌊L/3⌋` на адрес.
- Формула эмиссии эпохи `emission = sold × coeff` и границы coeff `[0.75, 1.5]`.
- Правила рынка §5.2 (эскроу, матчинг, запрет прямых переводов ANT §4.1),
  MOA §5.3, slashing.
- Вес в консенсусе `w_i = s_i / L_i` и делёж комиссий `F·(b_i/B)` — разнос
  «вес vs доход» (проблема №4) осознанно сохранён для наблюдения на стенде.
