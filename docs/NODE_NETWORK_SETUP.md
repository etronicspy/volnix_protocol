## 1. Архитектура сети

Volnix Protocol построен на **CometBFT** (форк Tendermint) и **Cosmos SDK**. Сеть состоит из узлов, которые обмениваются блоками и транзакциями по P2P-протоколу.

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                        DECENTRALIZED VOLNIX NETWORK                               │
├─────────────────────────────────────────────────────────────────────────────────┤
│                                                                                  │
│   ┌─────────────┐         P2P (26656)         ┌─────────────┐                   │
│   │  Validator  │◄────────────────────────────►│  Validator  │                   │
│   │   Node A    │                               │   Node B    │                   │
│   └──────┬──────┘                               └──────┬──────┘                   │
│          │                                              │                         │
│          │                                              │                         │
│          │         ┌─────────────┐                      │                         │
│          └─────────►│  Full Node │◄─────────────────────┘                         │
│                    │   Node C   │                                                 │
│                    └─────────────┘                                                 │
│                                                                                  │
│   RPC (26657)   gRPC (9090)   REST API (1317)                                    │
│   ─────────────────────────────────────────────                                  │
│   Клиенты подключаются к любому узлу для запросов и транзакций                   │
└─────────────────────────────────────────────────────────────────────────────────┘
```

**Ключевые принципы:**
- Все узлы одной сети используют **одинаковый genesis.json** и **Chain ID**
- P2P-соединения устанавливаются через `persistent_peers` и `seeds`
- Консенсус (PoVB) требует минимум 2/3 валидаторов для финализации блоков

## 2. Типы узлов

| Тип | Роль | Описание |
|-----|------|----------|
| **Validator** | Участвует в консенсусе | Подписывает блоки, должен быть в genesis.validators |
| **Full Node** | Репликация и синхронизация | Синхронизирует блоки, не участвует в консенсусе |
| **Seed Node** | Точка входа в сеть | Отдаёт адреса других узлов новым подключениям |

### Рекомендации по количеству
- **Testnet:** 2–4 валидатора
- **Mainnet:** 4+ валидатора (минимум 4 для BFT при 1 fault)

## 3. Схема соединений

### P2P-протокол (CometBFT)

```
Format: node_id@IP:port
Пример: a1b2c3d4e5f6...@192.168.1.10:26656
```

**Параметры в config.toml:**

| Параметр | Секция | Назначение |
|----------|--------|------------|
| `laddr` | `[p2p]` | Адрес прослушивания (обычно `tcp://0.0.0.0:26656`) |
| `external_address` | `[p2p]` | Публичный адрес для объявления пирам (NAT, облако) |
| `persistent_peers` | `[p2p]` | Список пиров для постоянного подключения |
| `seeds` | `[p2p]` | Seed-узлы для первоначального обнаружения сети |

### Связность (топология)

```
Полносвязная (рекомендуется для малых сетей):
  Node0 ↔ Node1 ↔ Node2 ↔ Node0

Через seed (для больших сетей):
  NewNode → Seed → получает addrbook → подключается к Validators
```

## 4. Настройка соединений

### 4.1 Получение Node ID

Node ID хранится в `config/node_key.json` и вычисляется из приватного ключа.

**Текущий способ (ручной):**
```bash
# Node ID хранится в config/node_key.json (поле id или вычисляется из priv_key)
# В CometBFT Go: nodeKey.ID() возвращает hex-строку
cat ~/.volnix/config/node_key.json
```

**Рекомендуется добавить команду:** `volnixd tendermint show-node-id` (см. раздел 7)

### 4.2 Редактирование config.toml

Файл: `~/.volnix/config/config.toml` (или `$HOME/config/config.toml` при `home`)

**На Node 0 (IP: 192.168.1.10):**
```toml
[p2p]
laddr = "tcp://0.0.0.0:26656"
external_address = "192.168.1.10:26656"
persistent_peers = "NODE1_ID@192.168.1.11:26656,NODE2_ID@192.168.1.12:26656"
```

**На Node 1 (IP: 192.168.1.11):**
```toml
[p2p]
laddr = "tcp://0.0.0.0:26656"
external_address = "192.168.1.11:26656"
persistent_peers = "NODE0_ID@192.168.1.10:26656,NODE2_ID@192.168.1.12:26656"
```

**На Node 2 (Full Node):**
```toml
[p2p]
laddr = "tcp://0.0.0.0:26656"
external_address = "192.168.1.12:26656"
persistent_peers = "NODE0_ID@192.168.1.10:26656,NODE1_ID@192.168.1.11:26656"
```

### 4.3 Переменные окружения (опционально)

CometBFT поддерживает переопределение через env:
```bash
export VOLNIX_P2P_PERSISTENT_PEERS="id1@ip1:26656,id2@ip2:26656"
# Зависит от реализации — в текущем коде не используется
```

### 4.4 Узлы за NAT / в облаке

Для узлов за NAT или в облаке:

1. **external_address** — публичный IP или домен:порт
2. **Проброс портов** — порт 26656 (P2P) должен быть доступен извне
3. **Проверка:** `nc -zv <IP> 26656` с другого узла

## 5. Порты и сетевые требования

| Порт | Протокол | Назначение |
|------|----------|------------|
| **26656** | TCP | P2P — обязателен для соединения узлов |
| 26657 | TCP | RPC — запросы статуса, блоков, транзакций |
| 9090 | TCP | gRPC — для REST API и backend |
| 1317 | TCP | REST API (если включён через Cosmos SDK) |

**Фаервол:** Открыть порт **26656** на всех узлах, участвующих в P2P.

## 6. Genesis и валидаторы

### 6.1 Одинаковый genesis на всех узлах

Все узлы должны использовать **один и тот же genesis.json**:
- `chain_id`
- `genesis_time`
- `app_state`
- `validators`

### 6.2 Добавление валидатора в genesis

Текущая реализация (`app/minimal_server.go`, `createGenesisFile`) создаёт genesis только с **одним** валидатором (локальным).

**Для multi-validator сети:**

1. **Собрать pubkeys всех валидаторов:**
   ```bash
   cat ~/.volnix/config/priv_validator_key.json
   # Извлечь pub_key (base64 или hex)
   ```

2. **Вручную отредактировать genesis.json** — добавить в `validators`:
   ```json
   {
     "validators": [
       {
         "address": "<ADDR1>",
         "pub_key": {
           "type": "tendermint/PubKeyEd25519",
           "value": "<BASE64_PUBKEY1>"
         },
         "power": "10",
         "name": "validator-0"
       },
       {
         "address": "<ADDR2>",
         "pub_key": { ... },
         "power": "10",
         "name": "validator-1"
       }
     ]
   }
   ```

3. **Скопировать genesis.json** на все узлы перед первым запуском.

### 6.3 Full Node (без валидатора)

Full Node **не** должен быть в `genesis.validators`. Достаточно:
- Инициализировать узел
- Скопировать genesis с первого валидатора
- Настроить `persistent_peers` на валидаторы

## 7. Реализованные возможности

### 7.1 Загрузка конфига из config.toml

**Реализовано.** При старте узла, если файл `config/config.toml` существует, он загружается и используется. Правки в `config.toml` (порты, `persistent_peers`, `external_address`, `moniker`) применяются при следующем запуске.

### 7.2 Команда `volnixd tendermint show-node-id`

**Реализовано.** Выводит Node ID для настройки `persistent_peers`:

```bash
./build/volnixd tendermint show-node-id -home testnet/node0
```

### 7.3 Moniker при инициализации

**Реализовано.** При `volnixd init <moniker>` значение moniker записывается в создаваемый `config.toml`.

### 7.4 Возможные доработки (опционально)

- **`volnixd network init-testnet`** — автоматическое создание multi-validator genesis и config
- **Порт gRPC** — настраиваемый порт gRPC для multi-node на одной машине

## 8. Чеклист развёртывания

### Перед запуском

- [ ] Собран бинарник `volnixd` (или `volnixd-standalone`)
- [ ] На каждом узле выполнен `volnixd init <moniker>`
- [ ] Genesis идентичен на всех узлах
- [ ] Chain ID совпадает
- [ ] Получены Node ID всех узлов

### Конфигурация

- [ ] `config.toml` на каждом узле: `persistent_peers` указывает на остальные узлы
- [ ] `external_address` задан для узлов за NAT/облаком
- [ ] Порт 26656 открыт на фаерволе

### Запуск

- [ ] Сначала запустить validator-узлы (если несколько — одновременно или с небольшим интервалом)
- [ ] Затем full node (если есть)
- [ ] Проверить подключение: `curl http://localhost:26657/net_info`

### Проверка

- [ ] `n_peers` > 0
- [ ] `latest_block_height` растёт
- [ ] Транзакции проходят через любой из узлов

## 9. Диагностика и отладка

### Полезные RPC-запросы

```bash
# Статус узла
curl http://localhost:26657/status | jq

# Информация о пирах
curl http://localhost:26657/net_info | jq

# Последний блок
curl http://localhost:26657/block | jq '.result.block.header.height'
```

### Типичные ошибки

| Симптом | Возможная причина | Решение |
|---------|-------------------|---------|
| `n_peers = 0` | Неверный `persistent_peers` или firewall | Проверить формат `node_id@ip:port`, открыть 26656 |
| Разный genesis | Genesis не скопирован | Убедиться, что genesis идентичен на всех узлах |
| Разные chain_id | Разные сети | Проверить `chain_id` в genesis |
| Узел не стартует | Несовместимость genesis/validators | Проверить логи, сбросить data и переинициализировать |

### Логи

- CometBFT пишет в stdout
- Уровень: `config.toml` → `[log]` → `level = "info"` или `"debug"`
